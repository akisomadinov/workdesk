# Безопасность

Workdesk находится в ранней стадии разработки. Пройденные тесты и проверки не заменяют независимый аудит. Гарантии невозможности взлома нет.

Не публикуй уязвимости вместе с токенами и корпоративными материалами. Используй приватное сообщение об уязвимости через GitHub Security Advisories репозитория, если эта функция включена. Если она недоступна, сначала открой issue без технических подробностей с просьбой предоставить приватный канал.

В локальном режиме приложение доступно на loopback и доверяет владельцу устройства. Этот режим не предназначен для сетевого доступа. В командном режиме нужны HTTPS, явный список разрешённых хостов, учётная запись владельца, защищённые ключи и резервное копирование. Подключения и токены принадлежат пользователям, документы открываются через членство в пространстве.

Уведомления защищены уникальными ключами в базе, очередью и проверкой состояния доставки перед внешним вызовом. Telegram не предоставляет идемпотентный ключ для sendMessage. После тайм-аута или сбоя после начала отправки состояние становится `uncertain`: автоматического повтора нет. После аварийной остановки незавершённые отправки также требуют ручной проверки.

Markdown не исполняет HTML/JavaScript. Внешние изображения не загружаются автоматически. Сервер проверяет доступ независимо от интерфейса, ограничивает попытки входа, не разрешает произвольные API-хосты в командном режиме и не следует перенаправлениям с токеном.

Ключ шифрования Linux-хранилища держи отдельно от каталога данных. SQLite содержит текст документов: используй шифрование диска и ограниченные права файлов. Не включай логирование тел HTTP-запросов или секретов.
